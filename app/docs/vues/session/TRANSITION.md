# Session — transition

## Objectif

Relier deux activités sans donner l’impression d’un menu ou d’une succession
arbitraire d’exercices.

## Contenu

Une transition tient généralement sur un écran très court :

- résultat ou constat utile de l’étape précédente ;
- lien narratif vers le nouveau contexte ;
- compétence qui va changer ;
- action « Continuer » ;
- téléchargement éventuel effectué en arrière-plan.

Exemple :

> Vous avez entendu Anna demander un café. Retrouvez maintenant la même manière
> d’exprimer un souhait dans le message de Mikko.

Cette phrase révèle le lien pédagogique sans donner la réponse exacte du prochain
exercice.

## Types de transition

- écoute vers répétition : passage du sens à la forme ;
- répétition vers rappel : retrait du modèle ;
- audio vers lecture : nouveau contexte et nouvelle modalité ;
- lecture vers jeu : vérification d’une information ;
- erreur vers reprise : ajout d’une aide ;
- activité vers bilan : synthèse des preuves recueillies.

## Règles

- durée de quelques secondes ;
- animation facultative et réduisible ;
- aucun score artificiel ;
- ne pas répéter les explications déjà comprises ;
- permettre de revenir si l’utilisateur a changé d’activité par erreur ;
- précharger le média suivant pendant la transition.

## Transition adaptative

Si une étape était difficile, la transition peut proposer :

- une reprise guidée ;
- l’affichage de la transcription ;
- un exemple supplémentaire ;
- la poursuite normale avec révision planifiée plus tôt.

L’utilisateur conserve le choix lorsqu’une aide rallonge sensiblement la session.
